# Dev Environment Gotchas

Moved from `AGENTS.md` so the always-loaded file stays inside Codex's instruction budget. Code-editing gotchas from the same list moved to the rules that load with those files: theme switching to `.agents/rules/gotchas-ui.md`, proxy debugging to `.agents/rules/api-surfaces.md`; the `@layer` order is in `.agents/rules/token-priority.md`. The safety rules (`artifacts/`, `tmux kill-server` / `portless prune`, transitive imports, `.npmrc` tokens) stay in `AGENTS.md`.

- Worktree ports are deterministic. Use `pnpm ports` or `pnpm ports watch` (arrows select, Enter opens, `k` confirms kill, `q` quits). The dashboard discovers active worktrees; browser tools use its Portless `🌐` URL, falling back to `.dev-frontend-port`, never a hardcoded port. `pnpm ports --json` lists each stack with its derived status; the state lives in each worktree's `.dev-stack.json` (`scripts/lib/dev-stack-state.js`), and the port files mirror it. `pnpm ports --json --sizes` and `pnpm run doctor` also give the `.next` split (dev output, dev cache, build cache, build output; sizes from `du`): an active stack's dev output grows about a GiB an hour.
- `pnpm run mem` reports each `next-server`'s CPU, port, worktree, and physical footprint via vmmap; `ps` RSS undercounts it ~50x. Next ≥16.3 is healthy at low single-digit GB; `vpk-system-clean` restarts servers at ≥6 GB. `pnpm run mem --brief` prints one line (swap in use, pressure level, live dev stacks, the largest by footprint, and under pressure the `pnpm ports kill <identifier>` for the largest idle one); `pnpm run check` shows it beside the main-health line, and the SessionStart hook shows it only under memory pressure, from stacks the sweep and those runs cache (it says how old). Nothing it prints is ever run for you.
- A new stack's ports skip every port that already listens (loopback included: the dev backend binds 127.0.0.1) and every port another worktree's port files record, scanning up from the slot's base, so it never lands on another stack's port when slots shift after a worktree is added. The chosen ports are written to the port files. `pnpm ports` and `pnpm run doctor` show a port file whose listener runs in another directory as held elsewhere, not as this stack's.
- No automation stops another worktree's stack that is in use. A stop requested from another worktree or by automation names itself (`VPK_DEV_STOP_BY`, `VPK_DEV_STOP_FROM`; `pnpm ports kill` and the vpk-system-clean sweep set them) and is refused (exit 6) while that stack has an agent process in it or recent activity (dev log, `.dev-stack.json` or git index written in the last 30 minutes; `scripts/lib/dev-stack-activity.js`). `pnpm ports kill <id> --force` overrides. Every stop, refused or not, is appended to the stopped worktree's `output/logs/<worktree>/dev-stops.log` with who asked, from where, and the caller's process ancestry.
- Runtime port files: `.dev-rovo-port`, `.dev-rovo-ports`, `.dev-frontend-port`, `.dev-backend-port`. `.claude/launch.json` (Claude preview configs) is also per-checkout: the SessionStart hook writes it via `scripts/write-claude-launch-config.js`; don't commit it.
- TypeScript checks authored project directories. Generated `output/` evidence and `public/1p/rovo-stage-kit` browser assets are excluded from file discovery; explicitly imported files remain type-checked.
- Fresh worktrees need their own `node_modules`. Managed worktrees copy ignored `.env*` and clone matching dependencies or run `CI=true pnpm install --prefer-offline`; manual worktrees must do this themselves. Do not run parallel pnpm validations until warmup completes.
- Tmux/Rovo launchers (`pnpm run dev:tmux:start`, `pnpm run rovo`, `pnpm run dev:rovo`, `pnpm run rovo:tmux:start`) seed `.env.local` from main or `.env.local.example`; copy/symlink it manually only for direct backend/frontend startup or provider bootstrap.
- `ASAP_PRIVATE_KEY` in `.env.local` already includes surrounding double quotes and literal `\n` escapes — do not add extra quotes.
- One backend per data directory. Each checkout's backend writes its own `backend/data/`, so worktree stacks never share it. On startup the backend takes `backend/data/backend.lock` (`backend/lib/backend-data-dir.js`). If another live backend holds it, the new one exits 1 and names that backend's pid, port and cwd. A lock left by a dead process is taken over automatically. `VPK_BACKEND_DATA_DIR` points a backend at another directory; the test fixture `backend/__fixtures__/start-backend.js` gives each test backend its own temporary one.
